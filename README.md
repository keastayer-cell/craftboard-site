# CraftBoard

Небольшая живая витрина моих проектов. Собрал ради интереса, без больших
планов — а она взяла и работает.

Сайт показывает проекты и краткое состояние VPS, на котором они размещены.
Фронтенд написан на React и Vite, статика отдаётся через nginx, а небольшой
локальный Python API собирает загрузку сервера и состояния systemd-сервисов.

## Адрес

- Production: https://craftboard.online
- VPS: Selectel, Ubuntu 24.04 LTS, 2 vCPU, 2 GB RAM, 40 GB

## Локальный запуск

```bash
cd craftboard-react
npm ci
npm run dev
```

## Проверки

```bash
cd craftboard-react
npm run lint
npm run build
node --test tests/status.test.mjs
```

Проверки API: `python3 -B -m unittest discover -s tests -v` из корня репозитория.

## Деплой

Push в `main` запускает GitHub Actions. Workflow собирает приложение и
атомарно переключает `/var/www/craftboard/current` на новый release.

Серверные файлы лежат в `ops/`:

- `nginx-craftboard.conf` — виртуальный хост nginx;
- `status.py` — локальный API статуса на `127.0.0.1:9191`;
- `status-api.service` — systemd unit для API.

## Статусы двух серверов

На главной сохранены две компактные плашки слева: сайт/VK-бот на `139.100.237.243`
и Telegram-бот на DigitalOcean `178.62.199.241`. В них сохранены прежние конфигурация, IP
и список проектов; связь и время обновления доступны в подсказке и на странице сервера. Подробные CPU, память, диск
и службы находятся на отдельных страницах серверов, открываемых по нажатию плашки.
Страницы серверов: `/server-selectel.html` и `/server-amsterdam.html`;
старый `/server.html` открывает Selectel.

`/api/status` работает на сервере сайта. Формат версии 2 содержит `servers.selectel`
и `servers.amsterdam`; общих метрик и объединённого списка служб больше нет.
Каждый сервер возвращает `host`, `metrics`, `services`, `connection`,
`checked_at`, `last_success_at`, `stale` и `error`.

Данные DigitalOcean поступают с `http://178.62.199.241:9192/status`:
это отдельный read-only `ops/project-status.py` в `/opt/project-status/`,
запущенный от `nobody`. На нём проверяются `tg-poll-bot` и `uptime-monitor.timer`.
Его установка и работа этим изменением не меняются.

Сайт обновляет данные каждые 30 секунд. API ограничивает запрос к DigitalOcean
тайм-аутом 3 секунды и кэширует результат 10 секунд. При потере связи сохраняет
последние полученные метрики, явно отмечает их устаревшими и не показывает
старые активные службы зелёными. Ответ источника старше 90 секунд считается
устаревшим. Если успешных данных ещё не было, показываются прочерки.
Сбой DigitalOcean не подменяет показатели Selectel и не скрывает его состояние.
При недоступности всего API браузер также сохраняет предыдущие метрики
с предупреждением; после восстановления показывает новые данные.

«Служба запущена» означает только `systemctl is-active`. Ответы ботов на команды,
доставка сообщений и работа бизнес-функций этим API не проверяются.
«Служба остановлена» и «Нет связи с сервером» — разные состояния.
